# Image Integration for Rhetorical Frontend

This document describes the new image integration functionality that allows the frontend to display images generated by Replicate's text-to-image models instead of just text messages.

## Overview

The frontend has been updated to handle both text and image messages from the backend. When the backend sends an image URL (generated by Replicate), the frontend will display the image in 3D space instead of text.

## New Components

### 1. Image3D Component (`src/components/commonComponents/Image3D.js`)
- Displays images in 3D space using Three.js
- Supports floating animation similar to Text3D
- Includes subtle glow effects for better visibility
- Automatically handles texture loading and rendering

### 2. Message3D Component (`src/components/commonComponents/Message3D.js`)
- Smart component that automatically detects message type
- Renders either Text3D or Image3D based on content
- Handles both string messages and structured message objects
- Maintains consistent positioning and scaling

### 3. Message Utilities (`src/utils/messageUtils.js`)
- Helper functions for message type detection
- Message processing and formatting utilities
- Backend response handling for different data formats

## Message Format Support

The system now supports multiple message formats:

### Text Messages
```javascript
// Simple string
"Hello World"

// Structured object (legacy)
{
  type: 'text',
  text: 'Hello World',
  timestamp: 1234567890
}

// New backend structure with Twilio fields
{
  sid: "SM1234567890",
  from: "+1234567890",
  body: "Hello World",
  imageUrl: null,
  imageGenerationStatus: "skipped",
  displayMode: "text",
  timestamp: 1234567890
}
```

### Image Messages
```javascript
// Direct image URL (legacy)
"https://example.com/image.jpg"

// Structured object (legacy)
{
  type: 'image',
  imageUrl: 'https://example.com/image.jpg',
  text: 'Generated image description',
  timestamp: 1234567890
}

// New backend structure with Twilio fields
{
  sid: "SM1234567890",
  from: "+1234567890",
  body: "Generate a beautiful sunset",
  imageUrl: "https://replicate.com/generated-image.jpg",
  imageGenerationStatus: "success",
  displayMode: "image",
  timestamp: 1234567890
}
```

## Backend Integration

The backend should send messages in one of these formats:

### For Text Messages
```javascript
{
  filtered: "Your text message here"
}
```

### For Image Messages (Recommended)
```javascript
{
  filtered: {
    sid: "SM1234567890",
    from: "+1234567890",
    body: "Generate a beautiful sunset",
    imageUrl: "https://replicate.com/generated-image.jpg",
    imageGenerationStatus: "success",
    displayMode: "image",
    timestamp: Date.now()
  }
}
```

### Display Mode Changes
```javascript
// Notify frontend of mode changes
socket.emit('displayModeChanged', {
  mode: 'image'  // or 'text'
});
```

## Key Features

### 1. Smart Message Detection
- Automatically detects message type based on `imageUrl` and `imageGenerationStatus`
- Only displays images when `imageGenerationStatus === 'success'`
- Gracefully handles failed image generation by falling back to text

### 2. Real-time Mode Updates
- Frontend listens for `displayModeChanged` events
- Visual indicator shows current display mode
- Automatic UI updates when switching between text and image modes

### 3. Robust Error Handling
- Handles failed image generation gracefully
- Fallback to text display for malformed messages
- Supports both new and legacy message formats

## Usage

### Basic Implementation
The Message3D component automatically handles message type detection:

```javascript
import { Message3D } from '../components/commonComponents';

// In your render method
<Message3D
  message={messageData}
  position={[0, 0, 0]}
  scale={[1, 1, 1]}
  color="#2f24c1"
/>
```

### Custom Message Processing
Use the utility functions for custom message handling:

```javascript
import { 
  isImageMessage, 
  getImageUrl, 
  getTextContent,
  processIncomingMessage,
  getDisplayMode,
  getImageGenerationStatus
} from '../utils/messageUtils';

// Process incoming message
const processedMessage = processIncomingMessage(rawMessage);

// Check message type
if (isImageMessage(processedMessage)) {
  const imageUrl = getImageUrl(processedMessage);
  const status = getImageGenerationStatus(processedMessage);
  // Handle image display
} else {
  const text = getTextContent(processedMessage);
  // Handle text display
}

// Get current display mode
const mode = getDisplayMode(processedMessage);
```

## Configuration

### Image Display Settings
- Default image size: 6x6 units in 3D space
- Animation speed: 0.3 (slower than text for better visual effect)
- Movement range: 80 units (slightly smaller than text)
- Opacity: 0.9 with subtle glow effect

### Text Display Settings
- Default scale: 0.9x1x0.5
- Animation speed: 0.5
- Movement range: 100 units

## Dependencies

The new functionality requires these Three.js dependencies:

## Error Handling

The system includes robust error handling:
- Graceful fallback for unsupported message types
- Texture loading error handling
- Default message display for malformed data
- Handles failed image generation gracefully

## Performance Considerations

- Images are limited to the last 5 messages (same as text)
- Texture loading is handled efficiently by Three.js
- Animation performance is optimized for smooth 60fps rendering
- Automatic cleanup of unused textures
